# Gamedistribution 游戏资源抓取脚本 - 操作文档

## 1. 简介

本脚本旨在使用 Node.js 和 Puppeteer 自动化地从 `gamedistribution.com` 抓取指定 H5 游戏的元数据（名称、描述、说明、标签、缩略图）和 `html5.gamedistribution.com` 上的完整游戏资源文件。脚本会尽可能保持原始游戏文件的目录结构。

**核心原理**:

- **Puppeteer**: 启动一个真实的 Chrome (Chromium) 浏览器来加载游戏页面，执行 JavaScript。
- **被动监听**: 拦截浏览器加载初始资源时发出的所有网络请求。
- **主动分析**: 递归地读取已下载的 JS, JSON, CSS 等文件内容，使用正则表达式和智能路径解析查找并下载其中引用的其他资源（包括相对路径）。
- **模式推断**: 基于已下载资源的路径模式，尝试猜测并下载后续关卡可能存在的资源。
- **反反爬虫**: 使用 `puppeteer-extra-plugin-stealth` 伪装浏览器指纹，并加入请求重试和延迟机制。

## 2. 主要特性

- **批量处理**: 支持在配置中定义多个游戏进行抓取 (当前为串行执行以保证稳定性)。
- **元数据抓取**: 自动从游戏商店页面提取游戏名称、发行商、描述、操作指南、分类、标签。
- **缩略图下载**: 自动抓取并保存游戏的缩略图 (通常是 `thumbnail.jpg` 或 `.png`)。
- **深度资源分析**:
  - 递归扫描 `.js`, `.json`, `.css`, `.xml`, `.atlas`, `.plist`, `.fnt` 等多种清单文件。
  - 同时使用正则表达式和 JSON 值分析来提取资源引用。
  - 支持解析 CSS `url(...)` 语法。
  - **智能相对路径解析**: 能正确处理 `../` 等相对路径。
  - 覆盖广泛的资源类型 (图片, 音频, 字体, 数据文件等)。
- **启发式关卡推断**: 尝试根据第一关的资源路径猜测后续关卡的资源路径，并探测已发现的最大关卡编号作为边界。
- **稳定性与反屏蔽**:
  - 使用 Stealth 插件减少被识别为机器人的概率。
  - 页面导航失败时自动重试。
  - 任务之间加入延迟，降低请求频率 (当前配置为单任务执行)。
  - 自动处理大文件下载时的缓存失效问题 (`evicted from inspector cache`)。
  - 自动跳过下载无效的 HTML 错误页面 (即使状态码为 200)。
- **保持目录结构**: 下载的资源文件会按照原始的相对路径保存在本地。

## 3. 先决条件

- **Node.js**: 建议使用最新的 LTS (长期支持) 版本。
- **npm**: 通常随 Node.js 一起安装。

## 4. 安装与设置

1.  **创建项目文件夹**: 在你的电脑上创建一个新的文件夹，例如 `game-scraper`。
2.  **保存脚本**: 将最新的脚本代码保存为 `scrape.js` 文件，放置在该文件夹内。
3.  **打开终端**: 在 `game-scraper` 文件夹中打开你的终端或命令行工具 (例如 CMD, PowerShell, Bash)。
4.  **初始化项目**: 运行 `npm init -y` 来创建一个 `package.json` 文件。
5.  **安装依赖**: 运行以下命令安装 Puppeteer 及其 stealth 插件：
    ```bash
    npm install puppeteer-extra puppeteer-extra-plugin-stealth
    ```
    (npm 会自动下载所需的 Chromium 浏览器，可能需要一些时间)。

## 5. 配置

打开 `scrape.js` 文件，找到顶部的 **全局配置区域** 进行修改：

- **`GAMES_TO_SCRAPE` (必需)**: 这是最重要的配置。它是一个包含多个游戏对象的数组。你需要为每个想抓取的游戏添加一个对象，格式如下：

  ```javascript
  {
      slug: "游戏名称或标识符",
      http_root: "游戏实例ID"
  }
  ```

  - `slug`: 访问 `https://gamedistribution.com/games/你的游戏名称`，URL 中 `games/` 后面的部分就是 `slug` (通常是小写字母和连字符)。 **示例**: 对于 `https://gamedistribution.com/games/black-pink-halloween-concert`，`slug` 就是 `"black-pink-halloween-concert"`。
  - `http_root`: 这是游戏实际资源 URL 中的**实例 ID**部分。访问游戏的 `html5.gamedistribution.com` 地址，例如 `https://html5.gamedistribution.com/rvvASMiM/589aeed18a104d34b7516dae0a3ad9c3/`，**最后一部分** `589aeed18a104d34b7516dae0a3ad9c3` 就是 `http_root`。**注意：不要包含末尾的 `/`**。

- **`CONCURRENCY_LIMIT` (可选)**: 同时运行的抓取任务数量。**强烈建议保持为 `1`**，以避免因请求过于频繁而被 `gamedistribution.com` 暂时屏蔽 IP (导致 `net::ERR_FAILED` 错误)。如果你想提速，可以尝试增加到 `2` 或 `3`，但需自担风险。

- **`STAGGER_DELAY_MS` (可选)**: 启动下一个抓取任务前的等待时间（毫秒）。当前设置为 `10000` (10 秒)，配合 `CONCURRENCY_LIMIT = 1`，能有效降低被屏蔽的风险。

- **`MAX_GUESSED_LEVEL_DEFAULT` (可选)**: 阶段 4 模式推断的默认最大关卡猜测上限。脚本会尝试根据已下载文件动态探测实际最大关卡，如果探测失败，则使用此默认值。

- **`RETRY_LIMIT` / `PHASE1_EXTRA_WAIT_MS` (可选)**: 网络重试次数和阶段 1 的额外等待时间，一般无需修改。

## 6. 执行脚本

1.  确保你已经在终端中进入了 `game-scraper` 文件夹。
2.  运行以下命令启动脚本：
    ```bash
    node scrape.js
    ```
3.  脚本会根据 `GAMES_TO_SCRAPE` 列表，按照 `CONCURRENCY_LIMIT` 和 `STAGGER_DELAY_MS` 的设置，逐个或并发地处理每个游戏。
4.  抓取过程可能需要较长时间，具体取决于游戏大小和网络速度。请耐心等待，观察终端输出的日志信息。

## 7. 输出结果

脚本执行完毕后，所有文件将保存在项目文件夹下的 `downloads` 目录中。

- 每个游戏会有一个以其 **实例 ID** (`http_root` 的值) 命名的子文件夹，例如 `downloads/589aeed18a104d34b7516dae0a3ad9c3/`。
- 在该子文件夹内：
  - `game_info.txt`: 包含抓取到的游戏元数据 (名称、描述等)。
  - `thumbnail.jpg` (或 `.png` 等): 游戏缩略图。
  - 其他文件和文件夹: 游戏的核心资源，会尽量保持其在服务器上的原始相对路径结构 (例如 `assets/level1/`, `Build/` 等)。

## 8. 重要注意事项与故障排查

- **`net::ERR_FAILED` 错误**: 这通常意味着你的 IP 因为请求过于频繁而被服务器暂时阻止。**最有效的解决方法是将 `CONCURRENCY_LIMIT` 设置为 `1`**，并确保 `STAGGER_DELAY_MS` 足够长 (例如 10000 毫秒或更长)。
- **元数据抓取失败/不准确**: `gamedistribution.com` 网站的 HTML 结构可能会变化。如果元数据抓取失败或内容错误，你需要检查 `scrapeMetadata` 函数内的 `page.evaluate` 部分，更新其中的 CSS 选择器以匹配最新的网页结构。
- **资源抓取不全 (终极限制)**: 即使有深度分析和模式推断，脚本仍然**无法**保证 100% 抓取所有资源。特别是那些 URL 是通过非常复杂的 JavaScript 逻辑动态生成，或者需要模拟复杂游戏操作才能触发加载的资源，很可能会被遗漏。这是静态分析方法的固有局限性。
- **性能**: 运行 Puppeteer 会消耗较多的 CPU 和内存。同时抓取多个大型游戏可能会导致系统卡顿。
- **法律与道德**: 请确保你有权抓取目标网站的内容。在进行任何抓取之前，请检查 `gamedistribution.com` 的 `robots.txt` 文件和用户服务条款 (Terms of Service)。尊重版权，请勿将抓取的资源用于非法或商业目的。本脚本仅供学习和技术研究使用。

## 9. 脚本主要阶段概览

脚本对每个游戏执行以下主要步骤：

- **阶段 0**: 抓取元数据和缩略图。
- **阶段 1**: 导航到游戏页面，被动监听并下载浏览器自动加载的所有初始资源。
- **阶段 2**: (如果适用) 解析 Unity 的 JSON 配置文件，下载其中明确引用的但可能在阶段 1 被跳过的文件。
- **阶段 3**: 深度递归分析所有已下载的清单文件 (JS, JSON, CSS 等)，解析相对路径，下载所有新发现的资源，直到没有新清单或新资源为止。
- **阶段 4**: (启发式) 基于阶段 1 下载的路径，探测最大关卡数，猜测并尝试下载后续关卡的资源。
